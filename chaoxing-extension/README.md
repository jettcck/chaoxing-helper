# 学习通刷课助手 v1.5.1（Edge / Chrome 插件）

课程视频一键倍速、自动播放、自动下一节、**接入免费大模型自动答题**（视频随堂测验 + 作业/章节测验）、**自动处理页面弹窗并连续刷完章节**。
答题请求由扩展后台发起，接口地址与 Key 只保存在本机 `chrome.storage.local`。

## 完整工作流（一次开到底）

```
进入课程章节
  └─ 自动播放视频 · 维持倍速 · 静音
       ├─ 视频内弹题  → 自动作答 → 关闭弹题 → 继续播放
       └─ 视频结束    → 自动进入下一节
  └─ 章节测验页
       ├─ 解析题干/选项 → 大模型作答 → 点击选中
       ├─ 全部答完     → 自动点整页「提交」（跳过「暂时保存」）
       ├─ 提交确认弹窗 → 自动点「确定提交」
       └─ 提交成功     → 自动翻到下一节（跨帧从目录树跳转）
  └─ 若弹出「当前章节还有任务点未完成，是否去完成？」
       └─ 自动点「下一节」继续（不会点「去学习」把流程卡住）
  └─ 检测到 chapterId 变化 → 自动重置状态，进入下一章节，循环
```

## 修复记录 · v1.5.0（"提交后太快点下一节，平台没记上已完成"）

现象：题目提交后几乎立刻跳到下一节，学习通还没来得及把任务点标成"已完成"，导致整章显示未完成 / 需重做。

根因：旧逻辑**一点「提交」就立刻把状态置为"已提交"**，并且 `ensureAdvance()` 只看这个标记就翻页——提交请求与页面状态更新还没完成，下一页就点了。

修复（提交与下一节之间强制隔离）：

1. **点击 ≠ 完成**：点「提交」只记录 `submitClickedAt`，**不再立即置 `pageSubmitDone`**；只有结果页出现（`我的答案/正确答案/得分/提交成功…`）或超时兜底（15s）才算确认。
2. **强制冷却间隔**：`ensureAdvance()` 必须同时满足
   - 距点击提交已过 `submitGap` 秒（**默认 3 秒，可在弹窗调 0/3/6/10**）；
   - 提交已被确认（结果页出现）。
   两者都满足才允许点「下一节」，否则状态显示"提交后等待平台记录：还需 Ns"。
3. **不重复提交**：等待期内 `maybeSubmitPage()` 直接返回，不会反复点「提交」。
4. **作答与提交之间也留 800ms**：选完最后一个选项后停顿，避免"选了就交"被判未完成。
5. 章节切换时重置 `submitClickedAt`，下一章重新计时。

> 慢一点反而更快：多等几秒，平台把"已完成"记上，就不用回头重做整章。

## 修复记录 · v1.4.2（结果页续进加固 + 版本可见 + 诊断增强）

仍停在结果页时，做了三件事让问题"要么自动解决、要么一眼可见"：

1. **结果页判定不再依赖内部标记**：新增 `resultsDetected()`，页面出现「我的答案 / 正确答案 / 答案解析 / 回答正确 / 回答错误」即视为已提交（`我的答案` 这类文案只在提交后出现）。
   `ensureAdvance()` 的放行条件由 `pageSubmitDone` 改为 `pageSubmitDone || resultsDetected()`——即使扩展自己的提交标记丢失（例如刷新过页面），也能凭页面文案续点「下一节」。
2. **跨帧代点**：本帧找不到「下一节」按钮时（按钮在别的 frame），每 6 秒广播一次 `GOTO_NEXT`，由持有按钮的 frame 执行 `clickNextChapter()`。
   （不采用"顶层帧深搜同源 iframe"的方案，避免两个 frame 同时点同一按钮导致连跳两节。）
3. **可见性排查**：
   - 弹窗标题右侧显示**当前版本号**（如 `v1.4.2`）——若显示的不是最新版，说明扩展没重载成功。
   - 状态区新增：`已提交标记` / `结果页` / `下一节按钮`（元素标签+class）。
   - 诊断输出新增：`下一节按钮：…` 与 `已提交标记/检测到结果页/本帧`。
4. **性能**：`findClickableByText` 先用 `textContent` 做廉价文本筛选、再对幸存者判可见，避免每 2 秒对全页元素做 `innerText`/`getBoundingClientRect` 触发重排。

> 定位"到底哪里没走到"的最快方式：点弹窗「诊断题目」，把输出发我。重点看 `下一节按钮` 那一行是否为「未找到」、以及 `已提交标记/结果页`。

## 修复记录 · v1.4.1（"答完题停在结果页不动"）

现象：题目答完并提交后，页面显示「我的答案：… 20.0 分 / 0.0 分」的结果视图，底部有「上一节/下一节」，但流程停住不动。

根因：学习通底部「下一节」是 **`<div class="jb_btn">下一节</div>`** 这类非标准按钮，**不在 `a / button / .btn` 上**。
旧 `findClickableByText` 只扫 `a, button, [role=button], .btn, .Btn, input[type=button]`，因此**根本没找到这个按钮**，`scheduleNextAfterSubmit` 轮询 24 次后放弃 → 停留。

修复：

1. **扩大可点击元素范围**：扫描 `a, button, span, div, li, p, strong, em, font, input, [role=button], [onclick]`。
2. **匹配策略改为"文本完全相等优先、取最内层"**：`<div class="jb_btn">下一节</div>` 文本正好等于「下一节」即命中；外层包裹层（如 `.prev_next` 文本为"上一节下一节"）因不等于而排除，避免点错或点到"上一节"。
3. **新增 `findNextButton()`**：文本匹配失败时，再按 `class/id` 含 `next` 的可点击元素兜底（并排除含「上一节/prev」的）。
4. **新增 `ensureAdvance()` 兜底续点**：`pageSubmitDone` 后每 tick 检查一次「下一节」，节流 4 秒、幂等，`scheduleNextAfterSubmit` 的轮询若失效它仍能把流程推下去。
5. 章节切换时同步重置续点/弹窗节流。

> 结果页没有提交按钮也没有视频，能且只能靠点页面「下一节」翻页；这一步现在可靠了。

## 修复记录 · v1.4.0（"卡在「任务点未完成」弹窗一动不动"）

现象：题目答完后，页面弹出「提示：当前章节还有任务点未完成，是否去完成？」（按钮「去学习」/「下一节」），流程就此卡死。

原因：旧 `skipDialogs()` 只认「确定/继续/知道了」这几个按钮文案，遇到「下一节」「去学习」一律不认识，于是什么都不点。

修复：

1. **弹窗语义识别**：新增 `findDialogs`/`classifyDialog`/`pickDialogButton`，把弹窗分为三类并各自选对按钮——
   - **任务点未完成**（含"未完成/还有任务/任务点"）→ 点 **「下一节」**（`autoNext` 打开时；本页仍有题没答完则先不跳过，交给答题流程）
   - **提交确认**（含"确定提交/交卷"）→ 点 **「确定提交」**
   - **普通提示** → 点 **「确定/继续/知道了」**
   - 一律**不点**「取消/放弃/暂离/暂时保存/稍后」
2. **按钮取最内层**：只点真正的按钮叶子节点，避免点到文本相同的包裹层；每次动作 2 秒节流，防止刷屏连点。
3. **章节切换自动重置**：新增 `checkChapterChange()`，监听 `chapterId/jobid/workId` 变化（换节后）重置 `pageSubmitDone` 与每题状态，解决"下一章后不再自动提交"。
4. 弹窗处理与"自动下一节"共用开关，无需新增配置。

> 视频随堂测验页没有 `<video>`，`ended` 事件不会触发，因此翻页靠轮询 + 跨帧广播；弹窗则靠上面的定时扫描处理。

## 修复记录 · v1.3.2（"做完无法自动提交 / 不跳下一节"）

现象：题目全部选好后停住，既不自动提交，也不跳到下一节。

三处修复：

1. **整页提交默认打开**：`autoSubmitPage` 默认值由 `false` 改为 `true`（弹窗「全部答完后自动点整页提交」默认勾选）。
2. **提交按钮匹配重写**：学习通答案是 `<div class="subBtn">提交</div>`（不是 `<button>`），旧选择器匹配不到。
   现按**文本精确度打分**选取（`提交/提交答案/提交试卷/确认提交/交卷/完成作答/确定提交`），并**排除「保存/暂存/暂离」**，避免误点"暂时保存"。
   覆盖 `button / input / a / div[class*=btn|sub|submit]`，且否决"包裹了另一个提交按钮的父节点"。
3. **提交后自动翻页**：提交成功后启动 `scheduleNextAfterSubmit`，每 1.5s 轮询一次（最多 24 次）查找
   `继续学习 / 下一节 / 下一章 / 返回课程`；轮询到第 6 次仍无结果，则向同 tab 其他 frame 广播 `GOTO_NEXT`，
   由持有目录树（`目录`/`下一节` 链接）的主 frame 完成跳转——解决"测验在子 frame、下一节入口在主 frame"的问题。
   翻页只执行一次（`pageSubmitDone` 幂等标记），避免重复提交。

> 视频随堂测验页没有 `<video>`，`ended` 事件不会触发，因此翻页必须靠上面的轮询 + 跨帧广播，不能只等视频结束。

## 修复记录 · v1.3.1（"点诊断题目没结果 / 未识别到题目"）

现象：在 `studentstudy`（视频 + 章节测验同页）上点「诊断题目」返回"未获取到解析结果"。

两个原因，均已修复：

1. **页面脚本是旧的**：改完插件后只重载扩展不够，已打开的页面仍跑旧脚本。→ **必须再 Ctrl+F5 刷新课程页**；弹窗失败提示里已写明这一步。
2. **题目在子 frame，而消息只取到主 frame 的响应**：`chrome.tabs.sendMessage` 每次只返回一个 frame 的响应。→ 改为后台向**所有 frame** 收集（`webNavigation.getAllFrames` + 逐帧 `sendMessage`），
   - 状态显示：取"题目数最多"的帧（`GET_BEST_STATE`）
   - 诊断输出：返回题目最多的那份（`DUMP_TAB`），并显示"扫描 N 个 frame，最多识别到 M 道题"
   - 一键答题/倍速/下一节：广播到所有 frame，各帧处理自己的内容

同时诊断输出增强：无题时列出候选元素（class、选项候选数、输入框数、文本片段）、iframe 数量与 src，便于直接定位模板差异。

## 二、识别异常时的诊断流程

弹窗底部「诊断」→ 点「诊断题目」，会输出：

```
页面：https://mooc1.chaoxing.com/mycourse/studentwork?...
识别到题目：5
候选节点：.TiMu=5 .Zy_TItle=5 .Zy_ulTop=5 li=... input=... video=0
---------- 第 1 题 ----------
容器：DIV.TiMu
题干[有效]：【单选题】中国的近代史，是指（ ）以来的中国的历史。
  A. 1840年｜选择器命中：input｜当前选中：是
  B. 1919年｜选择器命中：input｜当前选中：否
页面级提交按钮：提交
最近动作：已选好答案（AI）：【单选题】中国的近代史...
```

判断标准：
- `题干[无效]` → 该课程模板结构不同，把这段诊断发我再补选择器
- `识别到题目：0` → 题目容器不匹配，同样看「候选节点」计数
- 选项全部 `当前选中：否` 但动作显示已作答 → 选择器命中但页面未记录选中，需按结构补点击目标

## 四、使用

1. 进入视频页（`mooc1.chaoxing.com/mycourse/studentstudy?...`）或测验页（`.../studentwork?...`）
2. 勾选：自动播放、静音、自动下一节、出现题目自动作答、用大模型答题
3. 倍速：点 1x / 1.5x / 2x / 4x / 8x / 16x 立即生效并持续维持
4. 测验页：点「一键答题」自动选好全部答案；**「全部答完后自动点整页提交」默认开启**（v1.3.2），全部答完后自动提交并尝试跳下一节；不想自动交卷可取消勾选
5. 「状态」区显示：识别到题目数、已作答次数、AI 调用次数、缓存命中数、最近动作与错误

## 五、答题流程

1. 解析题干（`.Zy_TItle` 等）与选项（`.Zy_ulTop li` 等），剥离 `A.` / `A、` / `A 文本` 前缀并保留字母
2. 按「选项叶子节点归属」分组，一页多题不会串位
3. 请求大模型，要求只输出 JSON：`{"answer":"A"}` / `{"answer":"A,C"}` / 填空题文本
4. 答案映射：字母 / 全角字母 / 判断题「正确、错误」/ 选项文本 / 填空文本
5. 点击前清空旧选择 → 点击后校验选中态 → 未生效则换目标重试
6. 题目内有提交按钮则提交；整页提交开关开启时，全部题目答完后自动点击页面「提交」（跳过「暂时保存」）
7. 提交后按结果节点判定对错；答错则带「上次 X 判错」反馈重问并排除已错选项（重试 0–4 次）
8. 答案本地缓存（≤500 条）；被判定错误的答案不复用；同题干不重复调用模型
9. **弹窗处理**（每 2 秒扫描一次）：识别「任务点未完成 → 下一节」「提交确认 → 确定提交」「普通提示 → 确定」，绝不点「取消/暂时保存」
10. **提交成功 → 自动翻页**：优先找页面「下一节」（兼容 `<div class="jb_btn">下一节</div>` 等非标准按钮），本帧找不到则跨帧请目录树所在 frame 代点；结果页停留时由 `ensureAdvance()` 每 4 秒兜底续点
11. **换节自动重置**：`chapterId` 变化即清空每题状态与 `pageSubmitDone`，下一章继续自动答题/提交

## 八、常见问题

- **改完代码没生效**：`edge://extensions` 点「重新加载」+ 刷新课程页。
- **测试连接失败 401/403**：Key 错误或未开通；429 表示限流（智谱约 5 次/分钟，OpenRouter 约 20 次/分钟）。
- **点诊断无结果**：先在 `edge://extensions` 点「重新加载」，再 Ctrl+F5 刷新学习通页面，然后重新点诊断。
- **答题不动**：点「诊断题目」，看「识别到题目」是否为 0、题干是否 `[有效]`，以及"扫描 N 个 frame"里的 N 是否包含测验所在的子帧。
- **答案仍不对**：把「答错重试次数」调到 2–3 让模型带反馈重判；或换 `deepseek-chat`。
- **卡在「当前章节还有任务点未完成，是否去完成？」弹窗**：v1.4.0 已自动点「下一节」。若仍卡住，确认「自动下一节」开关为勾选；该弹窗按钮文案若与「下一节」不同（例如"继续下一节"），把按钮原文发我再补进匹配表。
- **下一章不再自动答题/提交**：v1.4.0 已按 `chapterId` 变化自动重置。若某课程换节不刷新 URL，请把课程链接发我。
- **答完题停在结果页不动**（显示"我的答案：… 20.0 分"）：v1.4.1 已能识别底部非标准「下一节」按钮并自动翻页。若仍不动，把底部按钮的 HTML（右键检查元素）发我。
- **弹窗提示页面脚本未加载**：当前标签页不是 chaoxing.com，刷新课程页即可。
